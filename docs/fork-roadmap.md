Complete and review each phase's acceptance checks, then obtain the user's explicit acceptance before starting the next phase or publishing a release. Keep upstream changes easy to merge by limiting edits to the active phase. ## Phase 0.5: upstream 0.1.17 integration

The upstream multiple-plate scene, slice, and export workflow replaces the earlier plan to build a separate multiple-plate implementation. Integrate the approved Prepare, Slicing, Export, Printing, settings, and version treatments against that native workflow. The proposed layer inspector redesign is deferred; keep the existing inspector and its encoded-value behavior. Preserve the fork's material colors, CTB timing and range overrides, resin conversions, saved filename pattern, installation identity, and manual update policy. The package version advances from 0.4.0 to 0.4.1 for upgrade ordering, while the UI identifies the upstream base as 0.1.17 and this fork iteration as stickninja r1. Package and upstream versions serve different purposes; see [fork build versioning](dev/fork-builds.md).

Acceptance requires the checks in [the Phase 0.5 record](upstream-0.1.17-acceptance.md) to be performed and recorded, followed by explicit user acceptance. A completed build or a matching mockup alone does not complete the phase.

Stage 1 preserves existing brace patterns, Cluster Spacing, and Apply/Clear behavior. Apply and live placement preserve manual braces; Clear All continues to delete all braces on the current model, including manual braces. Relative sizing uses the smaller actual parent shaft segment diameter at each generated brace's two attachment points. The new relative brace has one uniform diameter. Automatic bracing while placing is off by default, stays within the placed support's model and plate, and shares the placement's undo operation. Cluster/grid optimization, advanced placement, and support influence are outside this stage.

Stage 2 works on selected trunks on one model and its assigned plate. It reduces eligible grounded trunks by replacing their model contacts with branches on retained hosts, preserving contact positions and geometry. Preview must not mutate the support graph; applying a current proposal is one undoable support edit. Existing dependency, bracing, collision, and ownership constraints take precedence over reducing the count. Grid Optimization is now authorized by the combined-review exception above; later tools retain their acceptance gates. Acceptance of Stage 1 does not claim that its remaining manual/native or physical-print checks were performed.

## Phase 0.4 scope and acceptance

Phase 0.4 adds resin quantity/cost conversions for material/color profiles and per-layer motion and PWM overrides for CTB V4/V5, including encrypted variants. This version continues to use one shared printer and material selection. Range motion no longer requires firmware identification or confirmation, and there is no replacement gate. The user accepted the phase on 2026-09-28. The acceptance record distinguishes completed file and UI checks from remaining manual and hardware checks; the 0.4.0 release notes record the verified Windows package and upgrade checks.

Resin profiles retain a weight entry in grams or kilograms, or a volume entry in millilitres, and an uncured-liquid density in g/mL for each material/color. Convert between weight and volume only with a positive finite density; if density is missing or invalid, keep volume entry valid and do not assume a value. The app computes equivalent resin volume, print mass, and cost from the effective material settings. Existing volume-based profiles remain valid and keep their current values and behavior.

Build on the existing one-based range workflow and resolved per-layer export/inspector plan. Add motion and optional PWM overrides for individual model layers and inclusive model-layer ranges, excluding the startup dummy. Support Simple and Two Stage motion settings according to Settings Mode, including lift and retract distances and speeds, and the per-stage retract split for Two Stage. Restore separate bottom/normal PWM controls in Simple CTB, as already present in Two Stage and All Fields. Each range field can inherit independently; when ranges overlap, the later matching override wins per field. Bottom and normal settings remain the fallback. Two-stage constraints must remain valid, including retract distances relative to total lift. The LOD calculator uses effective overridden motion and must not silently overwrite raw user LOD or wait values; it must detect stale calculated values or require explicit reapplication. The inspector reads encoded values from exported output, and estimates use the effective motion.

Acceptance will verify:

- Grams/kilograms and millilitres convert using a positive finite uncured-resin density for that material/color, with expected volume, mass, and cost. Missing or invalid density does not block volume entry or lead to an assumed conversion value; legacy volume profiles load and round-trip unchanged.
- Layer, range, and bottom/normal fallback values resolve with one-based inclusive boundaries, excluding the startup dummy; per-field inheritance; later-range precedence; Simple and Two Stage Settings Mode behavior; and valid two-stage lift/retract relationships.
- Simple CTB retains separate bottom and normal PWM. A blank range PWM leaves the earlier matching PWM in place, or inherits the bottom/normal default when no range sets it. A finite 0–100% entry overrides that range, with the later matching range winning independently of timing and motion fields. Explicit range 0% encodes byte 0; a legacy default of 0 retains its existing full-power fallback. The startup dummy stays fixed at encoded PWM 1. The inspector shows the stored 0–255 byte and its percentage. Enabled per-layer timing rounds percentage to the nearest byte; legacy native defaults outside that plan retain their existing encoding.
- Calculated and estimated motion reflects effective overrides without silently replacing user-entered LOD or waits; stale results are detected or recalculation is explicitly applied. When a selected range spans different effective motion from defaults or overlapping overrides, calculate/preview per affected layer or split the range into homogeneous motion groups so one incorrect LOD value is not applied across the range.
- Enabled timing and range PWM support CTB V4/V5, plain or encrypted, in Simple, Two Stage, and All Fields. Range motion uses that CTB format gate only in Simple and Two Stage; existing mode validation still rejects motion overrides in All Fields. Neither feature depends on a firmware identification or confirmation field. Do not infer physical printer support from file encoding; verify observed behavior for each tested model and firmware separately. Invalid range PWM values block export.
- Persisted overrides, material/color variants, duplication, and import/export round trips retain the intended settings. Independently decode exported files and compare their motion values with the UI and inspector; distinguish file-content checks from actual hardware behavior and verify supported printer models separately.

## Release boundary

The fork originally started from the upstream `0.1.9` baseline and is now integrating `0.1.17` in Phase 0.5. Its first Windows package was **0.1.0**, separate from the accepted Phase 0.1 feature. The unsigned Windows x64 NSIS package uses product name **DragonFruit (stickninja)**, publisher **stickninja**, identifier `io.github.stickninja.dragonfruit`, and executable `dragonfruit-stickninja`. It has separate app data and profiles, leaves the official installation and `.voxl` registration intact, and omits automatic migration and COM thumbnail registration. The **0.2.0**, **0.3.0**, and **0.4.0** packages have passed optimized builds and upgrade installation checks. Updates are manual from the fork's releases until its own signed updater and feed are ready. See the [0.1.0](releases/0.1.0.md), [0.2.0](releases/0.2.0.md), [0.3.0](releases/0.3.0.md), and [0.4.0 release notes](releases/0.4.0.md).
