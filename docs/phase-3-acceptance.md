# Phase 0.3 acceptance: CTB timing and layer inspection

**Status:** Accepted by the user on 2026-09-26. This accepts the Phase 0.3 feature; release packaging is tracked separately.

This document defines the Phase 0.3 behavior and checks. The verification section records only checks actually performed. The remaining integrated app and hardware checks are pending until recorded with the build and profile fixture.

## Behavior

- A CTB material can opt into typed per-layer timing. Bottom and normal defaults independently store raw light-off delay, wait before cure, wait after cure, and wait after lift in seconds. A missing or disabled timing object keeps the prior CTB settings and export behavior.
- Ordered overrides target inclusive one-based model layer numbers, including individual layers when start and end match. Each field can inherit or override; the last matching rule for that field wins. Invalid values or ranges outside the model layer count produce an actionable export error.
- The Timing tab shows the effective model and supports a raw LOD calculator in Simple, Two Stage, and All Fields single-stage CTB modes. The calculator adds constant-speed lift and retract travel, optional measured motion-time correction, and target extra pre-exposure rest; it rounds to 0.01 s and applies only when the user clicks Apply. Explicit waits remain independent. CTB V4/V5, including encrypted variants, support this feature; unsupported versions or modes show an actionable message.
- The optional startup dummy inserts one file layer before real model layer 1. Its Z matches the first real layer; native output uses one gray-128 pixel, 0.01 s exposure, PWM 1, 0.1 mm first-stage lift, zero second-stage lift and timing waits, and inherited motion speeds. Real model Z and layer numbering remain unchanged in the editor. The CTB bottom count includes the dummy only when the original bottom count is positive.
- Sliced-file export and the inspector use the same resolved file-order plan. The inspector distinguishes model layer number from file layer number and identifies the dummy.
- The encoded-settings inspector is anchored on the left directly above the printer/material statistics card at the same width. Its body and the upper Printing panel share bounded scrolling space; both retain collapse controls.
- Profile save/reload, independent color variants, printer duplication, printer bundle import/export, and material bundle import/export preserve timing settings without sharing nested references.
- Reslice Now creates an unsaved preview and clears the previous saved path and completed action. Export is required to save the replacement artifact. This fixes the inherited stale “Saved to” display after reslicing, including when timing is turned off.

The calculator follows [UVtools `OperationCalculator.cs` lines 180–221](https://github.com/sn4k3/UVtools/blob/4774b6b40838094167998d307aea2a713dcc40dc/UVtools.Core/Operations/OperationCalculator.cs#L180-L221). The dummy values follow [`SuggestionWaitTimeBeforeCure.cs` lines 460–484](https://github.com/sn4k3/UVtools/blob/4774b6b40838094167998d307aea2a713dcc40dc/UVtools.Core/Suggestions/SuggestionWaitTimeBeforeCure.cs#L460-L484), and the CTB field layout is cross-checked against [`ChituboxFile.cs` lines 549–610](https://github.com/sn4k3/UVtools/blob/4774b6b40838094167998d307aea2a713dcc40dc/UVtools.Core/FileFormats/ChituboxFile.cs#L549-L610), all at commit `4774b6b40838094167998d307aea2a713dcc40dc`. These are file-format references. The user-reported LOD hardware check below covers one unspecified setup; physical behavior for other model/firmware combinations, including the reported Saturn 3 wait-before-cure cap and LOD bypass, and startup-dummy behavior still require device verification.

## Required acceptance checks

1. On Saturn 2 and Saturn 3 representative CTB printer profiles, exercise Simple and Two Stage modes in V4/V5. Confirm the Timing tab can set separate bottom/normal raw LOD and all three waits; existing CTB material controls remain usable when timing is disabled. Confirm unsupported V2/V3 or Tilting mode cannot silently export enabled timing.
2. Create individual and overlapping range overrides, including a field left blank for inheritance. Inspect model-layer 1, the last bottom layer, transition boundaries, normal layers, and the last layer. Confirm per-field precedence and one-based inclusive ranges; confirm invalid or out-of-bounds rules block export with a clear message.
3. Check calculator examples with single and two-stage motion, a 30 s target, and a correction value. Confirm the displayed motion breakdown and raw LOD match the formula, Apply changes only the selected bottom/normal/range LOD, and all explicit wait fields remain unchanged.
4. Export short V4/V5 CTB fixtures with and without startup dummy. Independently inspect binary header and per-layer records for counts, Z, exposure, LOD, three waits, motion, PWM, and first-layer dummy raster. Check encrypted variants separately. Compare the inspector with decoded records and verify legacy output when timing is disabled.
5. Save and reload timing profiles; duplicate a printer and create a color variant, then change each copy independently. Round-trip printer and material bundles and compare timing defaults, rule ordering, blank fields, and dummy flag.
6. Print a small representative file on Saturn 2 and Saturn 3 if hardware is available. Record observed rest timing and dummy behavior separately from encoded file values; do not infer firmware timing from CTB metadata alone.
7. Save a file, edit timing or switch Simple/Two Stage, then use Reslice Now. Confirm the old saved path is cleared, Export is available, and the old disk file remains unchanged until explicitly exported. Repeat after disabling timing; the old saved path must not remain attached to the new preview.

For additional checks, record the platform, build, material and printer profile fixtures, CTB version, and observed results. The user has accepted Phase 0.3; remaining coverage is listed below.

## Verification performed

- Focused TypeScript tests for timing rule precedence, transition boundaries, Simple/All Fields stage zeroing, separate bottom/normal Two Stage motion, dummy record shape, zero-PWM legacy fallback, calculator arithmetic, validation, and material persistence/clone/import passed locally on 2026-09-24 (8/8 in the focused run). The broader frontend regression run passed 20/20, and the TypeScript check passed.
- The focused native CTB tests passed (32/32). The full native engine suite passed 150 tests and had one failure in an unrelated Elegoo timing test. Comparison against the baseline by exact Git hashes confirmed that failure was unchanged; the full suite is still not recorded as a clean pass.
- Independently, the installed UVtools CLI decoded all eight V4/V5 and encrypted V4/V5 fixtures with startup dummy on and off. The decoded real-layer Z values remained unchanged, and raw LOD plus the three independent wait values were present in the layer records. Follow-up inspection passed all eight global-header default checks. A UVtools V4 dummy round trip also preserved 16 checked fields across all five layers.
- Six optimized Windows release builds passed, including the reslice-path fix and the requested left-rail inspector layout.
- In an isolated native app at 1280 × 800, the Timing defaults, range controls, and dummy option were readable. The Simple calculator produced 38.4 s raw LOD for a 30 s target and 40.4 s with 2 s motion correction. Apply changed only raw LOD; the material profile retained that value after saving and restarting the app.
- A fresh native V4 Simple export of a 10-layer block with startup dummy completed at 159,297 bytes. Independent UVtools inspection confirmed the encoded timing and layer fields. The inspector's file layer 1 dummy, file layer 2/model layer 1, and file layer 9/model layer 8 matched the decoded file.
- The final native Windows UI review verified the requested left-rail placement at 2560 × 1392 and 1280 × 800. At the smaller size, the inspector and statistics card both start at x = 14 px with 260 px widths and approximately 18 px between them; the upper Printing panel remains separate. Inspector collapse/reopen worked, its scroll reached PWM and both help paragraphs, and the Printing panel scrolled to Saved to and Send. TypeScript and focused component lint checks passed. A fresh V4 Simple dummy export completed in 135 ms of native slicing time, and the first encoded record displayed the expected timing. This supersedes the earlier adjacent-column layout review.
- A fresh native V5 encrypted Two Stage export without dummy completed at 183,779 bytes. Independent UVtools inspection passed for all 10 layers: no dummy, Z from 0.05 to 0.5 mm in 0.05 mm steps, 0.5 mm total height, bottom lift of 2 + 4 mm at 30 + 180 mm/min with retract at 180 + 60 mm/min and 1 mm second-stage retract distance, and normal lift of 1 + 5 mm at 60 + 240 mm/min with retract at 240 + 60 mm/min and 1 mm second-stage retract distance. Bottom/normal defaults and all overrides matched the encoded records. The raw encrypted settings flag independently decoded as `0x40`. The inspector's motion and file/model numbering matched the decoded file.
- A user reported that UVtools agreed with the DragonFruit settings they tested, and that manually setting LOD in a UVtools-modified file worked. A subsequent DragonFruit LOD hardware check was confirmed working, and the user accepted Phase 0.3 on 2026-09-26. The printer/model, firmware, and CTB version for that hardware check were not specified; it does not verify the full Saturn 2/Saturn 3 matrix.
- The 0.3.0 optimized frontend, TypeScript, native Windows, and NSIS builds passed. A silent 0.2.0-to-0.3.0 upgrade passed, and the installed app showed About version `0.3.0`. The installed version metadata, preservation checks, installer size, and checksum are recorded in the [0.3.0 release notes](releases/0.3.0.md).
- An earlier copied Two Stage file was stale because a successful reslice retained the prior saved-file path. In the native app, reslicing that saved Two Stage job after selecting a Simple profile with startup dummy returned Export as CTB and cleared Saved to. The preview showed 10 model layers and 11 file layers, a matching nine-minute estimate, and the expected first dummy record. The original saved file's SHA remained unchanged. Explicit export produced a new 250,189-byte CTB file; independent UVtools inspection confirmed the dummy and first real layer. This verifies the saved-path reset for this mode switch. Reslicing after disabling timing has not yet been checked in the native UI.
